# Эксперименты

Здесь будут скрипты обучения DQN (Режимы А и Б, Baseline 1/2, Proposed) и оценки на dev/тесте.

Зависимости обучения (torch и др.) — отдельный `requirements-train.txt`; версии и бюджет обучения
зафиксированы в протоколе (раздел 8, таблица 5). Сам файл в репозиторий пока не добавлен.

## Требования к коду экспериментов

1. Среда создаётся в одном модуле, и при его импорте вызывается `from sim import fast_road; fast_road.enable()`. Так ускорение включено в каждом процессе, включая воркеры, которые macOS запускает через spawn.
2. Состояние на момент вставки ego (после прогрева) для валидации, dev и теста рассчитывается один раз на пару (D, сид). Оно сохраняется в `start_states/` вместе с состоянием генератора случайных чисел и переиспользуется всеми политиками, ρ и режимами. Тест: эпизод из сохранённого состояния побитово совпадает с эпизодом, посчитанным с нуля.
3. Счёт — очередь независимых задач (запуск обучения или блок эпизодов ячейки), по процессу на ядро. В каждом процессе один поток: `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`, `OPENBLAS_NUM_THREADS=1`, `VECLIB_MAXIMUM_THREADS=1`, `torch.set_num_threads(1)`. При перезапуске готовые задачи пропускаются. На macOS очередь запускается через `caffeinate -i`.
4. Каждая задача выполняется целиком на одной машине. В её журнал пишутся машина, ОС, модель CPU, версии пакетов и хэш коммита.
5. До пилота на каждой машине счёта выполняются `python -m pytest -q sim/test_fast_road.py` и `python sim/bench.py fast`; время шага идёт в раздел 8 протокола. Когда появится боевой генератор трафика, тест эквивалентности переводится на него вместо упрощённого `sim/window_env.py`.
